# 도메인 모델

## 이 문서의 역할

코드를 읽지 않는 대신 여기를 읽는다. 그래서 이 문서는 개념 소개가 아니라 **구현이 따라야 하는 계약**이다. 상수, 판정식, 불변식이 여기 적힌 값과 다르면 구현이 틀린 것으로 본다.

프레임워크 이름이 한 번도 나오지 않아야 한다. 나오면 그건 아키텍처 문서로 갈 내용이다.

범위는 [MVP.md](MVP.md) 의 첫 릴리스에 맞춘다. 미룬 정책은 문서 끝에 따로 적는다.

## 도메인

> 러너가 한 번의 주행에서 시작부터 종료까지의 거리를 측정하고, 그 사이에 **응원받고 싶은 위치**를 지정해 두었다면 그곳에서 응원받는 것.

동사가 셋이다. **측정한다 · 지정한다 · 응원받는다.** 이 셋이 도메인이고, 나머지는 이 셋을 뒷받침한다.

정의를 제외 목록으로 두지 않는 이유가 있다. "소셜은 밖이다" 는 무엇이 밖인지만 말하고 무엇이 안인지 말하지 않는다. 그러면 새 기능이 들어올 때 판단 기준이 없다.

### 무엇이 어디에 속하나

| 개념 | 위치 | 근거 |
|---|---|---|
| 거리 측정, 위치 지정, 응원 | 핵심 | 정의 안의 동사다 |
| 페이스·구간 템포 | 지원 | 거리와 시간에서 나온다. 목적이 아니다 |
| 훈련 부하·페이스 존 | 지원 (미착수) | 정의를 고치지 않고 붙는다 |
| 지도 표시, 좌표 저장 | 일반 | 남이 만든 것을 쓴다 |
| 친구 비교·랭킹 | **다른 컨텍스트** | 응원의 주체가 자기에서 남으로 바뀐다 |

랭킹이 다른 컨텍스트인 이유가 이 정의의 값이다. 같은 `Run` 이라는 낱말을 쓰더라도 주체가 바뀌면 뜻이 다르다.

### 정의의 폭을 확인하는 방법

| 상황 | 판정 |
|---|---|
| 새 기능에 정의를 고쳐야 한다 | 너무 좁다. 핵심을 잘못 잡았다 |
| 정의를 고치지 않고 하위 도메인으로 붙는다 | 맞다 |
| 정의가 새 기능을 막지도 허락하지도 않는다 | 너무 넓다. 경계 구실을 못 한다 |

## 용어

| 용어 | 뜻 | 코드 이름 |
|---|---|---|
| 위치 | GPS 수신 한 건. 위치·정확도·속도·시각 | `Fix` |
| 지점 | 코스에서 응원이 오는 목표 한 곳 | `Waypoint` |
| 코스 | 순서가 있는 지점 목록. 비어 있어도 된다 | `Course` |
| 주행 | 시작부터 종료까지 한 세션 | `Run` |
| 궤적 | 주행 중 쌓인 경로와 누적 거리 | `Track` |
| 구간 | 지점 사이의 거리·시간·템포 집계 | `Split` |
| 템포 | 구간 하나의 페이스 | `SecondsPerKm` |
| 결손 구간 | 위치 수신이 뜸해 실제 경로를 모르는 구간 | `Gap` |

## 값 객체

단위를 숫자로 두지 않는다. 선행 검증에서 미터·초당미터·초당킬로미터가 모두 `number` 였고, 그 탓에 거리 계산과 페이스 계산이 서로를 잘못 먹는 실수가 났다.

| 값 객체 | 담는 것 | 규칙 |
|---|---|---|
| `Meters` | 거리 (m) | 음수 불가 |
| `MetersPerSecond` | 순간 속도 | 음수·비유한 불가. 없을 수 있음 |
| `SecondsPerKm` | 페이스·템포 | 거리 0 이면 만들 수 없음 (`null`) |
| `Millis` | 시간 간격 | 음수 불가 |
| `GeoPoint` | 위도·경도 | `distanceTo` 는 하버사인 |
| `Fix` | `GeoPoint` + 정확도 + 속도(없을 수 있음) + 시각 | 정확도·속도는 기기가 안 줄 수 있다 |
| `Waypoint` | 순번 + `GeoPoint` + 반경 + 출처 | 반경 30m 고정 |

페이스는 거리 0 에서 정의되지 않는다. `null` 을 반환하고 화면은 `--'--"` 로 적는다. 0 이나 무한을 넣으면 창 평균이 오염된다.

`Waypoint` 의 **출처**는 셋 중 하나다. `live`(달리며 터치), `track`(트랙에서 승격), `map`(지도에서 지정) 이다. 첫 릴리스는 `live` 와 `track` 만 만든다.

출처가 셋이어도 **지켜야 하는 것은 하나다. 지점은 코스 경로를 벗어나지 않는다.** 응원받고 싶은 곳은 자유롭게 고르되 코스 위여야 한다.

허용 오차는 임의로 정하지 않고 도출한다. 지점이 경로에서 `d` 만큼 떨어져 있고 도달 반경이 `r` 이면, 러너는 지점으로부터 최소 `d` 까지만 접근한다. 그래서 `d ≤ r` 일 때만 도달한다. 따라서 `COURSE_TOL` 을 `WAYPOINT_RAD` 와 같게 둔다.

| 출처 | 코스 위에 있는가 | 도달 보장 |
|---|---|---|
| `live` | 서 있는 자리라 자동 만족 | 있음 |
| `track` | 트랙 점이라 자동 만족 | 있음 |
| `map` | `Course` 가 검사한다 | 불변식이 지키면 있음 |

`map` 을 경고로 다루지 않는 이유가 이것이다. 경고는 사람이 무시할 수 있고 불변식은 못 한다.

## 집합체

### Run (주행)

주행이 뿌리다. 궤적·구간·현재 목표를 소유한다.

**갖는 행위**

| 행위 | 하는 일 | 왜 밖에 두지 않나 |
|---|---|---|
| `start(시작점)` | 대기에서 달리는 중으로 | 시작 조건이 주행의 상태에 달려 있다 |
| `accept(위치)` | 위치를 받아들이거나 버린다. 거리·구간·도달을 갱신하고 사건을 낸다 | **판단이 밖에 있으면 종료된 주행에 위치가 더 들어오는 사고를 막을 수단이 없다** |
| `finish(사유)` | 달리는 중에서 끝으로 | 종료 뒤 상태가 바뀌지 않아야 한다 |
| `currentTarget()` | 현재 목표 지점 또는 없음 | 순번 규칙이 주행 안에 있다 |

`accept` 가 이 모델의 중심이다. 정확도 컷·속도 상한·결손 판정·도달 판정이 전부 이 한 행위 안에서 일어나고, 밖에서는 위치를 넣는 것 외에 할 수 있는 일이 없다.

**상태 기계**

```
대기 ──시작(사용자)──> 달리는 중 ──종료(사용자)──> 끝
                          │
                          └──무이동 3분──> 끝
```

전이는 이 셋뿐이다. 다른 경로로 상태가 바뀌면 구현이 틀렸다.

**불변식**

1. **시작은 사용자 행위로만 일어난다.** 위치가 코스 시작점과 맞아도 저절로 시작하지 않는다
2. 지점 도달은 순번대로만 판정한다. 2번을 먼저 지나도 1번이 남아 있으면 1번이 현재 목표다
3. **코스가 비어 있어도 주행할 수 있다.** 지점 없이 거리·페이스만 쌓인다
4. **지점을 다 지나도 끝나지 않는다.** 현재 목표가 없음이 되고 주행은 계속된다. 최종 목표라는 개념을 두지 않는다
5. 종료된 주행은 다시 바뀌지 않는다

4번이 규칙을 하나로 만든다. 지점이 0개여도, 다 지나도, 주행은 사용자가 끝낼 때 끝난다. 규칙이 하나면 예외 처리가 없다.

### Track (궤적)

`Run` 안에 사는 개체다. 따로 뿌리를 두지 않는다. 거리 측정이 주행의 핵심이므로 주행 밖에서 궤적만 바꿀 이유가 없다.

**갖는 행위**

| 행위 | 하는 일 | 불변식 |
|---|---|---|
| `extend(증분, 시각)` | 누적 거리를 늘리고 경로 점을 남긴다 | 거리는 감소하지 않는다 |
| `markGap(시각)` | 결손 구간으로 표시한다 | 결손은 지우지 않는다 |

누적 거리와 경로 점을 쌓는다. 거리는 **두 방식을 동시에** 기록한다.

| 이름 | 방식 | 용도 |
|---|---|---|
| `distSpeed` | 도플러 속도 × 경과 시간 | 기본값 |
| `distGeo` | 좌표 간 하버사인 합 | 비교·대조용 |
| `dist` | 아래 선택 규칙의 결과 | 화면·구간에 쓰는 값 |

**위치 한 건을 받았을 때의 거리 증분 선택**

```
dt = 이번 시각 − 지난 시각
sp = 이번 위치의 속도 (없으면 null)
ac = 이번 위치의 정확도 (없으면 null)

1. ac 가 ACC_CUT 보다 크면        → 증분 0     (도심 반사 위치를 버린다)
2. sp 가 있고 dt ≤ GAP_S 이면     → 증분 = sp × dt
3. 그 밖에는                      → 증분 = 하버사인 거리
4. 증분 ÷ dt 가 SPEED_MAX 를 넘으면 → 증분 0   (튀는 위치를 버린다)
```

도플러 속도를 먼저 쓰는 이유는 정확도다. 좌표 차이를 합하면 잡음이 지그재그로 쌓여 거리가 늘어난다. 표본을 촘촘히 받는다고 이 오차가 줄지 않는다. 오히려 커진다. 정확도는 수신 간격이 아니라 필터로 올린다.

`dt` 가 `GAP_S` 를 넘으면 그 구간을 **결손 구간**으로 표시한다. 지도에서 실선이 아니라 회색 점선으로 그린다. 받지 않은 경로를 직선 실선으로 그리면 강 위를 달린 그림이 나온다.

경로 점은 5m 이상 움직였을 때만 추가하고 상한은 `TRACK_MAX` 다.

### Course (코스)

순서가 있는 지점 목록. 지도에서 탭한 순서가 아니라 **만든 순서**가 번호가 된다.

주행과 따로 사는 뿌리다. 여러 주행에 걸쳐 저장되고 다시 불려 나온다. 주행은 코스를 식별자로 참조한다.

**갖는 행위**

| 행위 | 하는 일 | 불변식 |
|---|---|---|
| `markHere(좌표)` | 달리는 중 현재 위치를 지점으로 추가 | 순번은 연속이다 |
| `promote(트랙점)` | 저장된 궤적의 한 점을 지점으로 올린다 | 궤적 순서를 따라 정렬된다 |
| `pin(좌표)` | 지도에서 지정. **경로에서 `COURSE_TOL` 을 넘으면 거절한다** | 지점은 코스를 벗어나지 않는다 |
| `remove(순번)` | 지점을 뺀다 | 뒤 순번을 당겨 연속을 지킨다 |

`pin` 만 거절할 수 있다. 나머지 둘은 좌표가 이미 경로 위라서 거절할 상황이 없다.

저장 한도는 `MAX_ROUTES` 이며, 넘치면 가장 오래된 것을 내보내고 알린다.

## 정책

정책은 모두 **순수 함수**다. 상태와 입력을 받아 새 상태와 사건을 낸다. 시계도, 저장소도, 음성도 부르지 않는다. 현재 시각이 필요하면 주입받는다.

### 상수

| 이름 | 값 | 근거 |
|---|---|---|
| `ACC_CUT` | 60 m | 이보다 부정확한 위치는 거리에 넣지 않는다 |
| `SPEED_MAX` | 10 m/s | 사람이 낼 수 없는 속도. 넘으면 버린다 |
| `GAP_S` | 15 초 | 이보다 뜸하면 결손 구간 |
| `WAYPOINT_RAD` | 30 m | 지점 반경. 도심 오차를 감안한 값. 조절 항목을 두지 않는다 |
| `COURSE_TOL` | 30 m | 지점이 코스 경로에서 떨어질 수 있는 한계. `WAYPOINT_RAD` 와 같아야 도달이 보장된다 |
| `START_TOL` | 50 m | 저장된 코스 시작점과 같다고 볼 오차 |
| `MAX_ROUTES` | 20 | 코스 저장 한도 |
| `TRACK_MAX` | 2,500 | 경로 점 상한. 5m 간격이면 약 12km |
| `TRACK_STEP` | 100 m | 사후 지점 승격 목록의 간격 |
| `IDLE_MS` | 180,000 | 무이동 판정 시간 |
| `MOVE_MIN` | 10 m | 10초에 이만큼 움직이면 달리는 중으로 본다 |
| `TICK_MS` | 10,000 | 페이스 표본 단위 |
| `TICK_WIN` | 3 | 페이스 창 (30초). 10초 표본은 값이 튄다 |

### 페이스·템포 정책

```
paceOf(거리, 시간) = 거리가 0 이면 null, 아니면 (시간초 ÷ (거리m ÷ 1000))
창페이스(틱목록, 시작, 개수) = 그 범위의 거리 합과 시간 합으로 paceOf
구간템포(구간) = paceOf(구간 거리, 구간 시간)
```

창을 쓰는 이유는 표본 크기다. 틱 하나는 GPS 잡음에 그대로 흔들린다.

틱은 **위치 수신 시점에** 닫는다. 타이머는 화면이 꺼지면 조절되므로 믿지 않는다.

### 결손 틱 정책

선행 검증에서 GPS 가 652초 끊겼고, 위치 수신 시점에 틱을 닫는 방식이라 **한 틱이 652초를 담았다.** 그 틱이 창 평균에 그대로 들어가 페이스 비교를 망가뜨렸다.

```
틱 경과 시간이 TICK_MS × TICK_WIN 을 넘으면
    그 틱은 창 계산에 넣지 않는다
    결손으로 기록하고 창을 비운다
```

### 무이동 정책

선행 검증 규칙에 구멍이 있었다. 5m 미만이면 누적하고 30m 이상이면 되돌리는데, **5m 와 30m 사이는 어느 쪽도 아니어서** 아주 느리게 걷는 동안 누적이 멈춘 채로 남았다.

```
틱 이동거리 < MOVE_MIN  →  무이동 시간 누적
그 밖에                 →  무이동 시간 0 으로
누적이 IDLE_MS 를 넘으면 → 주행 종료
```

경계를 `MOVE_MIN` 하나로 모아 구멍을 없앤다.

### 도달 정책

```
현재 목표까지의 거리 ≤ WAYPOINT_RAD  →  도달
```

도달하면 구간을 닫고 다음 지점을 현재 목표로 올린다. 남은 지점이 없으면 현재 목표는 없음이 되고 주행은 계속된다.

### 지점 생성 정책

세 경로가 같은 결과를 낸다. 순번이 부여된 `Waypoint` 하나다. 다른 것은 좌표를 어디서 얻는가와 출처 표시다. 세 경로 모두 `Course` 의 행위이며 `Course` 가 불변식을 지킨다.

| 행위 | 좌표 출처 | 출처 표시 | 거절 조건 |
|---|---|---|---|
| `markHere(위치)` | 그 시각의 마지막 위치 | `live` | 위치가 아직 없음 |
| `promote(궤적, 인덱스)` | 궤적의 그 점 | `track` | 인덱스가 궤적 밖 |
| `pin(좌표)` | 사용자가 준 좌표 | `map` | **경로에서 `COURSE_TOL` 초과** |

`markHere` 는 위치가 아직 없으면 거절한다. 시작 직후 첫 위치가 오기 전에 누를 수 있으므로 이 경우를 사건으로 알린다.

`promote` 는 궤적 위의 점만 받는다. 임의 좌표를 받으면 `pin` 과 같아지므로 인덱스로만 받는다.

`pin` 은 좌표와 경로 사이의 최단 거리를 측정하고 `COURSE_TOL` 을 넘으면 거절한다. 경로가 없는 자유 주행에서는 `pin` 을 쓸 수 없다. 벗어날 기준이 없으면 불변식을 지킬 수 없다.

## 도메인 사건

정책은 음성이나 알림을 직접 부르지 않는다. 사건을 내고 밖에서 받아 처리한다. 이렇게 두면 도메인이 음성 합성기를 몰라도 되고, 시험할 때 사건 목록만 확인하면 된다.

| 사건 | 언제 | 밖에서 하는 일 |
|---|---|---|
| `RunStarted` | 사용자가 시작 | 음성 안내 |
| `WaypointMarked` | 지점 생성 | 짧은 확인음·진동 |
| `WaypointMarkFailed` | 위치가 없어 실패 | 안내 |
| `WaypointArrived` | 지점 도달 | 알림, 응원, 구간 템포 읽어주기 |
| `GapDetected` | 결손 구간 발생 | 기록 |
| `RunFinished` | 종료 | 최종 페이스 안내, 저장 |

## 시험 가능성

도메인이 순수하면 **주행 하나는 위치 목록에 대한 접기 연산**이다.

```
최종상태 = 위치목록.reduce(정책적용, 초기상태)
```

그래서 두 가지가 가능해진다.

1. **합성 위치로 단위 시험.** 일정 속도, 급감속, 15초 결손, 정확도 200m 잡음, 652초 단절을 각각 만들어 넣는다. 경계 조건은 합성이 더 정확하게 만든다
2. **실측 로그 재입력.** 실제 주행 기록을 그대로 넣어 회귀 시험으로 쓴다. 회귀 가치가 있으므로 앱이 기록을 낼 수 있게 되면 표본으로 추가한다

시작은 1번으로 한다. 2번이 없어도 막히지 않는다.

## 첫 릴리스 뒤로 미룬 정책

만들지 않는다는 뜻이 아니라, 응원이 통하는지 확인한 뒤에 추가한다는 뜻이다. 판정식은 선행 검증에서 이미 확인했으므로 그때 그대로 쓴다.

| 정책 | 뼈대 |
|---|---|
| 점수 | 틱 이동거리가 `MOVE_MIN` 이상이면 기본 점수 |
| 피버 | 현재 창페이스가 직전 창의 1.05배를 넘으면 3틱 동안 점수 2배 |
| 되찾음 | 피버가 끝나는 틱에 발동 당시보다 빨라졌으면 보너스 |
| 배지 | 프로필 누적값에 대한 술어 목록 |
| 강아지 | 누적 점수의 구간 조회 |

## 옮기지 않는 것

| 선행 검증에 있던 것 | 왜 안 옮기나 |
|---|---|
| 백그라운드 진단 도구 | 웹의 한계를 재는 도구였고, 네이티브에선 물음 자체가 사라진다 |
| 무음 오디오 유지 | 웹에서 실행 맥락을 유지하려던 우회책 |
| 화면 유지 요청 | 네이티브 백그라운드 위치가 대체한다 |
| 로그 배치 전송·보고서 제출 | 개발 단계 계측이었다. 필요하면 다시 짜되 도메인 밖에 둔다 |
| 지점 좌표 직접 입력 | 세 경로가 대체한다 |
| 지점 반경 조절 | 30m 고정. 사용자가 고를 이유가 없다 |
