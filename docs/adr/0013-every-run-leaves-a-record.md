# ADR 0013. 모든 달리기는 기록으로 남고, 기록은 자기 경로를 갖는다

- 상태: 채택
- 날짜: 2026-08-21
- 관련: [ADR 0011](0011-splits-close-on-passage-average-pace-main.md), [ADR 0012](0012-saved-course-keeps-its-runs.md), `docs/DOMAIN.md` 기록 정책, [#38](https://github.com/idean3885/cheer-runner/issues/38)

## 맥락

실제로 뛰고 나니 뛴 기록을 볼 곳이 없었다. 요약(거리·시간·페이스·구간)은 저장되지만,

1. **달리기별 경로가 남지 않는다.** 마지막 달리기의 경로만 코스 기준 경로로 덮어써 남고, 그 전 달리기의 경로는 사라진다. "어떤 경로로 달렸는지" 는 기록마다의 물음이다.
2. **기록 전체를 보는 자리가 없다.** 마지막 달리기 카드(직전 1건)와 코스별 «기록 보기»(코스에 붙은 것)뿐이라, 코스 없이 달린 기록은 어디서도 보이지 않는다.

MVP 는 달리기 기록 목록을 미뤘지만("종료 요약만 있으면 한 번은 돌아본다"), 실사용 첫 주에 바로 필요해졌다.

## 결정

**모든 달리기는 코스 유무와 무관하게 기록으로 남고, 기록은 자기 경로를 갖는다.**

| 항목 | 결정 |
|---|---|
| 남는 시점 | 종료. 사용자가 누르든 무이동으로 스스로 끝나든 같다 |
| 담는 것 | 시각 · 거리 · 시간 · 평균 페이스 · 구간 목록 · 코스 연결 · 표시용 경로 |
| 경로의 형태 | 결손으로 끊긴 조각 배열. 이어 그리면 지나지 않은 길이 경로로 보인다 |
| 경로의 크기 | `REC_PATH_MAX` 로 솎는다. 원본 궤적(`TRACK_MAX` 2,500점)을 다 들면 기록 상한까지 쌓였을 때 파일이 메가 단위가 된다. 표시용이라 정밀도 손실이 문제되지 않는다 |
| 보관 상한 | `RUNS_MAX` 건. 넘치면 가장 오래된 것부터 밀려난다. 기기에만 두는 파일이라 무한히 쌓지 않는다 |
| 코스 삭제와의 관계 | 무관하게 남는다 (ADR 0012 그대로) |

화면은 기록 목록(최근순)과 상세(경로 지도 · 전체 통계 · 구간 페이스)로 나눈다. 목록이 자리를 갖는 화면이 되므로 달리기 화면에서 여는 길을 둔다.

## 결과

- 코스 없이 달린 기록도 볼 수 있다. 기록이 코스의 부속이 아니게 된다
- 이 결정 이전의 기록에는 경로가 없다. 재료가 없어 복원하지 않고, 상세에서 경로 없음으로 표시한다 (ADR 0011·0012 와 같은 판단)
- 밀려난 기록은 돌아오지 않는다. 상한을 늘리는 것은 정책 변경이고 이 표의 값만 고치면 된다
