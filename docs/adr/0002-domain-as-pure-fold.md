# ADR 0002. 도메인을 위치 목록에 대한 순수 접기 연산(fold)으로 둔다

- 상태: 채택
- 날짜: 2026-08-12
- 관련: `docs/DOMAIN.md`, `docs/ARCHITECTURE.md`

## 배경

이 앱은 손으로 시험하기 어렵다. PoC 에서 그 비용을 그대로 치렀다.

- 좌표를 바꾸려면 실제로 이동해야 한다
- 백그라운드 거동을 보려면 화면을 끄고 달려야 한다
- 한 번 확인에 20분 이상
- 실기기 로그를 데스크탑으로 옮기는 과정이 번거로워, 앱에서 서버로 전송하는 경로를 따로 만들어야 했다

그 결과 결함이 늦게 드러났다. 거리 15% 미측정, 결손 구간을 직선 실선으로 그려 강 위를 달린 그림, 오디오가 조용히 꺼진 문제가 모두 실제 달리기를 마치고 나서야 보였다.

## 결정

**달리기 하나를 위치 목록에 대한 접기 연산으로 정의한다.**

```
최종상태 = 위치목록.reduce(정책적용, 초기상태)
```

`정책적용(상태, 위치) → (새 상태, 사건 목록)` 은 순수 함수다. 시계도 저장소도 음성 합성기도 부르지 않는다. 현재 시각이 필요하면 `ClockPort` 로 주입받는다.

부수 효과는 사건으로 낸다. 음성·알림·저장은 사건을 받는 쪽에서 한다.

## 무엇이 달라지나

| | PoC | 이 결정 이후 |
|---|---|---|
| 페이스 계산 확인 | 20분 달리기 | 단위 시험 몇 밀리초 |
| 결손 구간 처리 확인 | GPS 가 끊길 때까지 기다림 | 15초 빈 위치 목록을 만들어 넣음 |
| 정확도 잡음 처리 확인 | 도심에서 재현 시도 | 정확도 200m 위치를 섞어 넣음 |
| 회귀 방지 | 없음 | 실측 로그가 고정 표본 |

마지막 줄이 이 결정의 핵심 이득이다. **PoC 가 이미 수집한 실제 달리기 로그를 표본으로 옮긴다.** 강 위를 달린 그 달리기, 652초 단절이 있던 그 달리기가 회귀 시험 자료가 된다. 코드는 버리고 데이터는 가져간다.

## 기각한 대안

**화면과 함께 시험한다 (React Native Testing Library 중심).** 화면 시험은 화면이 깨졌는지만 알려준다. 이 앱에서 틀리면 아픈 것은 거리·페이스·점수이고, 그건 화면 밖에 있다. 화면 시험을 안 짜는 게 아니라 우선순위를 뒤에 둔다.

**실기기 자동화 (Detox·Maestro).** 백그라운드 위치 거동은 결국 실기기로 봐야 하므로 언젠가 필요하다. 다만 그건 통합 확인이고, 정책 정확성을 여기에 맡기면 왕복이 다시 분 단위로 돌아간다.

**시계를 도메인이 직접 읽는다.** `Date.now()` 를 정책 안에서 부르면 틱 경계·결손 판정·무이동 판정 시험을 짤 수 없다. 포트로 분리한 비용은 인자 하나이고, 얻는 것은 시간 관련 정책 전부의 시험 가능성이다.

## 받아들이는 대가

**연결 코드가 늘어난다.** 위치를 받아 정책에 넣고 사건을 꺼내 어댑터로 넘기는 층이 생긴다. PoC 는 콜백 안에서 바로 화면을 고쳤으니 그 층이 없었다.

토이 앱에서 이 대가는 작지 않다. 그래도 지불하는 이유는 검증 수단이 실기기밖에 없는 상태로는 코드를 읽지 않는 작업 방식이 성립하지 않기 때문이다. 문서와 CI 로 판단하려면 CI 가 판단할 대상이 있어야 한다.

## 결과

- `domain` 은 어떤 것에도 의존하지 않는다. `dependency-cruiser` 로 강제한다
- `domain` 커버리지 하한 90%. 다른 계층에는 커버리지 하한을 걸지 않는다
- PoC 로그를 `test/fixture/` 로 옮기는 작업을 첫 이슈에 포함한다
- 정책이 사건을 내는 형태이므로, 음성 문구 변경이 정책 시험을 깨지 않는다
