# ADR 0006. 버릴 코드 대신 제품 안의 진단 화면으로 0 단계를 확인한다

- 상태: 채택
- 날짜: 2026-08-13
- 관련: [ADR 0004](0004-replay-adapter.md) (0 단계 방식만 대체)

## 맥락

ADR 0004 는 0 단계를 **버릴 코드**로 확인하기로 했다. 근거는 이랬다.

> 만든 것을 다 쌓고 마지막에 막히면 쌓은 것 전부가 걸린다.

이 근거는 위험을 옳게 지목했지만 처방이 어긋났다. **위험을 없애는 것은 코드를 버리는 것이 아니라 첫 조각을 얇게 두는 것이다.** 버리든 남기든 첫 조각이 얇으면 막혔을 때 잃을 것이 없다.

그리고 실제로 만들어 보니 그 조각이 위치 어댑터 하나와 화면 하나였다. 포트 경계가 이미 정해져 있어서 어댑터는 버릴 것이 아니라 그대로 쓸 물건이었다.

## 결정

**0 단계를 제품 안의 진단 화면으로 확인한다.** 하단 탭으로 진단과 주행을 나누고, 0 단계를 통과하기 전에는 주행 화면을 만들지 않는다.

| | 버릴 코드 | 진단 화면 |
|---|---|---|
| 첫 조각 크기 | 얇음 | 얇음 (같음) |
| 막혔을 때 손실 | 없음 | 없음 |
| 통과 후 어댑터 | 버림 | 그대로 씀 |
| 실측 디버깅 | 다시 만듦 | 그대로 씀 |

진단 화면이 통과 후에도 값을 내는 것이 결정을 가른 지점이다. 실기기에서만 드러나는 문제는 앞으로도 계속 나오고, 그때마다 필요한 것이 배경 위치 건수와 권한 상태다.

## 무엇이 확인됐나

1차 측정이 판정 불가로 끝나면서 진단 화면 자체의 결함 둘이 드러났다. 버릴 코드였다면 이 학습도 함께 버렸다.

| 결함 | 왜 판정이 불가능했나 |
|---|---|
| 기록을 메모리에만 두었다 | 배경 이벤트로 앱이 깨어나면 실행 맥락이 새로 만들어져 기록이 사라진다. 받았어도 0으로 보인다 |
| 거리 필터가 걸려 있었다 | 정확도에 딸린 기본 거리 필터가 적용돼 제자리에서는 갱신이 오지 않았다. 움직이지 않은 것과 배경이 중단된 것을 구분할 수 없다 |

둘 다 어댑터와 저장 경계의 문제이고, 고친 결과가 제품에 남는다.

## 결과

- 화면은 진단과 주행 둘. 조립 지점에서 탭으로 고른다
- 배경 맥락과 화면 맥락 사이의 통로는 파일 하나뿐이다. 메모리로 전달하지 않는다
- 거리 필터를 없앤다(`distanceInterval` 0). 그러면 iOS 가 자기 주기로 갱신을 보내므로 제자리에서도 판정할 수 있다
- 시간 기준(`timeInterval`)은 Android 전용이다. iOS 에서 이것으로 제자리 문제를 풀려 했던 것이 처음의 오판이었다
- ADR 0004 의 재생 어댑터와 배속 결정은 그대로 유효하다. 이 결정은 0 단계 방식만 대체한다
