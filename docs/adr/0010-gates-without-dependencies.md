# ADR 0010. 관문을 의존 없는 스크립트로 두고 빌드는 관문에 넣지 않는다

- 상태: 채택
- 날짜: 2026-08-14
- 관련: [ADR 0003](0003-machine-gates-replace-code-review.md) (유지. 수단만 바뀐다), `docs/ARCHITECTURE.md`

## 맥락

ADR 0003 은 「규칙을 CI 에서 실패하게 만든다」를 정하고 수단으로 `dependency-cruiser`·TypeScript·eslint·커버리지 하한을 적었다. 그 뒤 이슈 여섯 건이 지나갔고, **적힌 장치가 하나도 설치되지 않았다.** CI 자체가 없었고, 시험은 어시스턴트가 손으로 돌렸다.

그 상태에서 계층 위반이 실제로 생겼다. 진단 화면이 어댑터 셋을 직접 부르고 있었고, 사람은 코드를 읽지 않으므로 보지 못했다. 위반을 찾은 것은 관문을 만들려고 의존 관계를 훑었을 때다.

측정값이 수단 선택을 갈랐다.

| 항목 | 값 |
|---|---|
| 도메인·응용·진단 시험 전체 | 0.28초 |
| 관문 넷 전체 (계층·구문·함수 크기·시험) | 1.9초 |
| 앱 네이티브 빌드 | 분 단위 |
| 화면 확인 (시뮬레이터) | 분 단위 + 사람이 그림을 봄 |

## 결정

**관문은 표준 라이브러리만 쓰는 스크립트로 두고, 모든 PR 에서 돈다. 네이티브 빌드와 화면 확인은 관문에 넣지 않는다.**

| 두는 것 | 무엇을 막나 |
|---|---|
| 계층 규칙 | 도메인이 플랫폼을 알게 되는 것. 그 순간 도메인 시험에 기기가 필요해진다 |
| 구문·import 해석 | 번들이 깨지는 가장 흔한 두 원인 |
| 함수 크기 (40줄, 도메인·응용) | 한 함수가 판정과 집계를 겸하는 것 |
| 도메인·응용 시험 | 계약대로 도는지 |

설치 단계를 없앤 이유는 속도가 아니라 **관문이 안 도는 상태를 만들지 않기 위해서**다. 의존이 붙으면 판 올림·잠금 파일·캐시가 관문의 실패 원인이 되고, 그 실패는 규칙 위반과 구분되지 않는다. 실패가 규칙 위반만 뜻할 때 관문이 신뢰된다.

타입 검사는 두지 않는다. 이 프로젝트는 순수 자바스크립트이고, 단위 혼용을 막는 일은 값 객체와 도메인 시험이 이미 한다. 두지 않기로 한 것을 문서에서 주장하지 않도록 `README`·`ARCHITECTURE` 의 관문 목록을 실제와 맞췄다.

## 결과

얻는 것은 초 단위 관문이다. 문서만 바뀐 PR 에서도 부담이 없고, 실패하면 원인이 규칙 위반 하나다. 관문 넷이 실제로 실패하는 것을 일부러 깨서 확인했다.

대가는 검사의 정밀도다. 계층·함수 크기 검사는 파서가 아니라 문자열 규칙으로 돌고, 이 프로젝트의 코드 형태(함수 선언과 함수 표현식만 쓴다)에 맞춰져 있다. 형태가 바뀌면 검사가 틀린 값을 낼 수 있다.

빌드를 관문에 넣지 않은 대가는 네이티브 설정 깨짐이 늦게 드러나는 것이다. 그것은 기기로 나갈 때 확인되고, 그 왕복은 어차피 사람이 한다.

**다시 볼 조건은 둘이다.** 검사가 오탐이나 미탐을 내면 그때 도구로 옮긴다. 그리고 코드 형태가 바뀌어(타입스크립트 전환, 화살표 함수 도입) 문자열 규칙이 깨지면 같은 판단을 다시 한다.
