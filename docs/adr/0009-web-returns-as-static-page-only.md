# ADR 0009. 웹은 정적 페이지로만 돌아온다

- 상태: 채택
- 날짜: 2026-08-14
- 관련: [ADR 0001](0001-cross-platform-choice.md) (유지), `docs/ARCHITECTURE.md` 2층, [#20](https://github.com/idean3885/cheer-runner/issues/20)

## 맥락

앱을 만드는 동안 웹 프로토타입을 확인 도구로 남겨 뒀고, 그 결과 **같은 도메인 규칙이 앱과 웹에 각각 구현된 상태**가 됐다. 정리 시점을 「앱 쪽 시험이 같은 표본으로 같은 판정을 낼 때」로 두었고, 그 조건이 차서 걷었다.

걷기 직전 상태가 이 결정의 근거다. 한쪽만 고치는 실수가 이미 시작돼 있었다.

| | 앱 | 웹 |
|---|---|---|
| 코스 보관함·시작 조건 가드·알림음 | 있음 | 없음 |
| 지점 이탈 판정·페이스 표본 하한 | 있음 | 없음 |
| 화면 용어 | 달리기 | 이전 낱말 |
| 시험 | 103건 | 9건 (웹 페이지 대상) |

**그 실수가 사고로 보이지 않은 이유는 시험이 각자를 봤기 때문이다.** 웹 시험은 웹만 보고 앱 시험은 앱만 본다. 규칙이 두 곳에 있으면 한쪽만 고쳐도 두 시험이 모두 초록이다.

그런데 웹이 돌아올 자리가 남아 있다. 스토어 등록에 개인정보 처리방침 주소가 필요하고, 앱을 남에게 넘길 때 설치 안내가 필요하다. 도메인(`cheer-runner.idean.me`)도 예약해 둔 상태다. 「웹을 쓰지 않는다」로 두면 그 자리가 왔을 때 판단이 흔들린다.

## 결정

**웹은 정적 페이지로만 돌아온다. 도메인 규칙을 한 줄도 두지 않는다.**

경계선을 판정 가능한 형태로 둔다. 아래 중 하나라도 필요하면 그것은 정적 페이지가 아니다.

| 필요해지는 것 | 판정 |
|---|---|
| 글·링크·그림 | 정적 페이지. 만든다 |
| 거리·페이스 계산 | 정적 페이지가 아니다 |
| 지점 도달 판정 | 정적 페이지가 아니다 |
| 좌표·코스 저장 | 정적 페이지가 아니다 |
| 위치 구독 | 정적 페이지가 아니다 |

결정한 것은 웹의 기술이 아니라 **계약의 소비자 수**다. `DOMAIN.md` 를 읽고 구현하는 것이 하나여야 한다.

## 결과

얻는 것은 규칙을 고칠 때 볼 곳이 한 곳이라는 사실이다. 계약을 바꾸면 구현 하나와 시험 하나만 따라온다.

대가로 내는 것은 확인 속도다. 브라우저를 띄워 즉시 보던 경로가 없어지고, 시뮬레이터 그림과 도메인 시험으로 대신한다. 그림은 빌드를 한 번 거치므로 왕복이 길다.

**다시 볼 조건은 하나다. 웹이 제품 표면이 되는 경우.** 러너가 웹에서 달리기를 시작하는 것이 범위에 들어오면 이 결정은 유효하지 않다. 그때는 웹에 규칙을 다시 구현하는 것이 아니라 도메인을 두 컨테이너가 공유하는 모듈로 떼어내고, 이 기록을 대체한다.

경계선에 걸리는 요구가 오면 그것 자체가 다시 볼 신호다. 정적 페이지에 계산이 한 줄 필요해지는 순간이 두 벌 상태가 다시 시작되는 지점이다.
