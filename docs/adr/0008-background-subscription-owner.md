# ADR 0008. 배경 구독의 주인을 파일에 적고 분배를 한 곳에 모은다

## 상태

채택

## 맥락

배경 위치 구독은 앱에 하나뿐이고 쓰는 쪽은 둘이다. 진단과 달리기.

여기에 세 제약이 겹친다.

| 제약 | 내용 |
|---|---|
| 맥락이 새로 만들어진다 | 앱이 종료된 뒤 위치 이벤트로 깨어나면 메모리에 아무것도 없다 |
| 등록이 앱보다 오래 산다 | 해제를 부르기 전까지 살아 있고 iOS 가 계속 앱을 깨운다 |
| 진단은 스스로 해제한다 | 만료되면 구독을 끊는다. 그것이 앱이 계속 깨어나던 결함의 해결책이었다 ([ADR 0006](0006-diagnostic-screen-over-throwaway-spike.md)) |

셋이 겹치면 결함이 하나 나온다. **달리기가 걸어둔 구독을 진단이 받으면 달리는 중에 측정이 멈춘다.** 진단은 자기 세션 기록이 없으므로 만료로 판단하고 구독을 끊는다. 러너는 화면을 꺼둔 상태이므로 그것을 알 수 없다.

처음 구조에서는 배경 처리기를 화면이 등록했다. 화면 둘이 각각 등록하면 나중에 뜬 쪽이 앞을 덮는다. 그리고 앱이 배경에서 깨어난 경우에는 화면이 없어 아무도 등록하지 않는다.

## 결정

세션 기록에 주인을 적고, 배경 위치를 누구에게 줄지 한 곳에서 정한다.

```
세션 기록  { owner, startedAt, expiresAt }

배경 위치 도착
  → 기록의 주인을 읽는다
  → 그 주인이 등록한 처리기에 넘긴다
  → 주인이 없거나 모르는 주인이면 구독을 해제한다
```

분배는 `application/BackgroundRouter` 가 갖고, 조립은 `application/wiring` 이 모듈 최상위에서 한다. 화면이 아니라 조립 지점이 하는 이유는 배경 맥락에는 화면이 없기 때문이다.

주인 없는 구독을 해제하는 것을 기본 동작으로 둔다. 남겨두는 쪽이 안전해 보이지만, 아무도 끄지 않는 구독이 배터리를 먹는 것이 이미 확인된 결함이다.

## 결과

얻는 것은 남의 구독을 끊지 않는다는 보장이다. 이 결함을 잡는 시험 넷을 두었고 기기 없이 돈다.

| 시험 | 확인하는 것 |
|---|---|
| 달리기가 걸어둔 구독을 진단이 받지 않는다 | 달리기 중 측정이 멈추지 않는다 |
| 진단이 걸어둔 구독은 진단이 받는다 | 분배가 반대로 되지 않았다 |
| 주인 없는 구독은 해제한다 | 아무도 끄지 않는 구독이 남지 않는다 |
| 모르는 주인이 적혀 있으면 해제한다 | 이름을 바꾼 뒤 남은 기록으로 멈추지 않는다 |

대가는 한 번에 하나만 측정할 수 있다는 점이다. 달리기 중에 진단을 시작하면 주인이 바뀌어 달리기가 위치를 잃는다. 지금은 진단을 개발자만 보므로 문제가 아니지만, 화면에서 막지 않고 있다.

다시 볼 조건은 둘을 동시에 돌려야 할 때다. 그때는 구독을 하나 더 두는 것이 아니라 한 처리기가 두 세션에 나눠 주는 쪽을 먼저 본다. 구독을 늘리면 iOS 가 앱을 깨우는 횟수가 늘어난다.
