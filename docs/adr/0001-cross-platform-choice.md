# ADR 0001. 크로스플랫폼 기반을 React Native + Expo 로 둔다

- 상태: 채택
- 날짜: 2026-08-12
- 관련: `docs/ARCHITECTURE.md`, 선행 PoC (`geofence-poc`)

## 배경

PoC 로 순수 웹에서 확인한 결과 하나가 이 결정의 출발점이다. **iOS 웹은 백그라운드에서 위치를 받지 못한다.** 측정으로 세 층을 갈라 확인했다.

| 층 | 결과 |
|---|---|
| 오디오 세션 | 살아 있음 (복귀 시 요소 재생, 컨텍스트 running) |
| JS 실행 | 살아 있음 (57초 중 30회) |
| 오류 콜백 | 살아 있음 (`3:Timeout expired` 2회) |
| 위치 수신 | 0건 |

콜백이 오고 있으므로 코드가 위치를 요청한 것은 맞고, 시스템이 응답하지 않았다. iOS 웹에는 "항상 허용" 권한이 없고 설정에 항목도 생기지 않는다. watch 재시작 2회도 통하지 않았다. 우회 경로가 남아 있지 않다.

따라서 네이티브로 감싸야 한다. 남은 물음은 무엇으로 감싸는가다.

## 결정

**Expo 기반 React Native.**

## 판단 기준이 바뀐 과정

이 기록이 결정보다 중요하다. 처음 든 근거가 전제 변화로 무효가 됐다.

**첫 근거 — 언어 전이.** TypeScript 는 Stack Overflow 2025 기준 43.6%, Dart 는 5.9%. TypeScript 는 백엔드(NestJS)·인프라 코드(CDK·Pulumi)·도구로 이어지지만 Dart 는 Flutter 밖에서 갈 곳이 거의 없다. 백엔드 개발자에게 남는 것이 다르다.

**전제 변화.** 작성자가 코드를 읽지 않고 설계와 도메인만 본다고 확인됐다. 그러면 언어 숙련이 쌓이지 않으므로 위 근거가 사라진다.

**바뀐 근거 — 생성 정확도와 네이티브 설정면.** 코드를 읽지 않는 조건에서는 "돌려보고 틀렸으니 다시" 가 유일한 검증 수단이고, 그 왕복 횟수가 곧 공수다.

| 기준 | React Native (Expo) | Flutter |
|---|---|---|
| 학습 데이터 규모 | npm 이 pub.dev 의 약 70배 | 작음 |
| 첫 시도 정확도 | 타입 정의·상태 초기화·오류 처리까지 대체로 그대로 동작 | 골격은 나오나 세부 수정이 잦음 |
| 네이티브 설정 | `app.json` + 설정 플러그인 — JavaScript 설정이라 AI 가 안정적으로 고침 | Gradle·Xcode 프로젝트를 직접 만짐 |
| 백그라운드 위치 | `expo-location` 1차 지원, 무료 | 조합이 필요하거나 유료 SDK |

네이티브 설정면이 결정적이다. Xcode 프로젝트 파일과 Gradle 스크립트는 AI 가 가장 못 다루는 곳이고, Expo 의 지속 네이티브 생성은 그 층을 설정 파일 뒤로 감춘다.

## 기각한 대안

**Flutter.** 정적 타입과 널 안전성으로 AI 실수를 빌드 단계에서 잡는 이점이 실재하고, 2026 로드맵이 안정화 쪽이라 판 흔들림도 적다. 정해진 방식이 거의 하나라 세션마다 설계가 흔들리는 문제도 덜하다. 그럼에도 기각한 이유는 첫 시도 정확도다. 컴파일러가 뒤에서 잡아주는 것보다 애초에 덜 틀리는 쪽이 왕복을 더 줄인다. 국내 모바일 공고 수(Flutter 165건 대 React Native 69건)에서 Flutter 가 앞서지만, 채용은 이 결정의 기준이 아니게 됐다.

**Capacitor.** 앞선 대화에서 한 번 권한 안이다. PoC 의 `index.html` 1,900줄을 그대로 쓰고 위치 계층만 갈아끼우면 몇 시간에 끝난다는 것이 근거였다. 재작성 공수가 문제되지 않는다고 확인되면서 그 근거 전부가 사라졌다. 중간 단계를 하나 늘리는 셈이 되어 기각했다.

**벗어난 React Native (Community CLI).** `ios/`·`android/` 를 직접 소유하는 방식. 2026 기준으로 Expo 가 공식 시작 경로이고, 설정 플러그인이 커스텀 네이티브 코드까지 덮으므로 예전의 "관리형에선 못 한다" 제약이 없다. 직접 소유할 이유가 없다.

## 받아들이는 대가

**판 올림 때 이전 작업이 생긴다.** React Native 0.82 에서 구 아키텍처가 제거되고 0.85(2026-04)·Expo SDK 55~56 로 강제 이전이 끝났다. 네이티브 코드를 품은 서드파티는 그때 점검이 필요했다. 토이 앱 규모에서는 반나절 일로 보고 감수한다.

## 결과

- 검증 순서는 iOS 먼저(작성자 기기), Android 다음(지인 기기)
- iOS 기기 설치는 로컬 Xcode 의 무료 서명으로 한다. 7일마다 재설치되지만 검증 단계에서는 답이 먼저 나온다. 유료 계정(연 99달러)은 앱을 계속 키우기로 정한 뒤에 산다
- Android 는 EAS 클라우드 빌드로 APK 를 뽑는다. 로컬 도구가 필요 없고 계정 비용도 없다
- 제조사 배터리 관리가 Android 백그라운드 위치를 죽이는 사례가 있으므로, 배터리 최적화 예외 안내를 화면에 넣는다
