# 결정 기록 작성 기준

이 디렉토리는 되돌리기 어려운 결정과 그 근거를 담는다. 작성자가 코드를 읽지 않으므로 여기 적힌 것이 판단의 근거 전부다.

## 형식

Michael Nygard 의 다섯 절을 쓴다.

| 절 | 담는 것 |
|---|---|
| 제목 | `ADR NNNN. 무엇을 어떻게 한다` 형태의 완결 문장 |
| 상태 | 아래 상태 표 참조 |
| 맥락 | 무엇이 이 결정을 강제했나. 측정값이 있으면 표로 |
| 결정 | 한 문장. 그 아래 무엇이 결정했는지 |
| 결과 | 무엇을 얻고 무엇을 대가로 내는가. 다시 볼 조건 |

## 분량 상한 50줄

Nygard 는 1~2페이지를 말한다. 이 프로젝트는 50줄로 고정한다.

넘으면 절을 축약할 문제가 아니라 **범위 밖의 내용이 포함된 것이다.** 실제로 ADR 0005 가 104줄이었고, 계획 한 절과 다른 문서에 이미 있는 한 절이 들어 있었다. 두 절을 제외하니 47줄이 됐다.

## 쓰는 때

셋 중 하나에 해당할 때만 쓴다.

| 조건 | 예 |
|---|---|
| 되돌리는 비용이 큰 결정 | 크로스플랫폼 기반 선택 |
| 계층 경계나 포트 계약을 바꾸는 결정 | 도메인을 순수 접기 연산으로 두기 |
| 이미 한 결정을 다시 보는 경우 | 캐패시터 재검토 |

세 번째가 이 프로젝트에서 실제로 값을 낸 자리다. 뒤집힐 때 필요한 것은 **무엇을 확인하면 결론이 바뀌는가** 한 줄이고, 그 한 줄이 없으면 같은 논의를 처음부터 반복한다.

## 쓰지 않는 것

| 넣지 않는 것 | 어디로 |
|---|---|
| 계획, 일정, 단계 | `MVP.md` |
| 계층·포트·강제 장치 명세 | `ARCHITECTURE.md` |
| 상수, 판정 순서, 정책 | `DOMAIN.md` |
| 변경 이력 | 커밋 메시지와 PR |

Nygard 의 원문은 ADR 이 "glorified change log" 가 아니라고 명시한다. 무엇을 했는지가 아니라 **왜 그것을 골랐는지** 를 적는다.

## 상태

| 상태 | 뜻 |
|---|---|
| 제안 | 아직 결정되지 않음 |
| 채택 | 현재 유효 |
| 대체됨 (ADR NNNN) | 다른 결정이 이것을 뒤집었음 |
| 폐기 | 전제가 사라져 결정 자체가 무의미해짐 |

결정을 **뒤집을 때** 는 새 ADR 을 작성하고 이전 것의 상태를 `대체됨` 으로 변경한다. 이전 문서를 수정하지 않는다. 틀린 판단도 기록이다.

결정을 **재검토하고 유지할 때** 는 새 ADR 을 작성하고 이전 것은 수정하지 않는다. 새 ADR 의 관련 항목에 `(유지)` 로 적는다. ADR 0005 가 0001 에 대해 이 형태다.

## 번호

`NNNN-영문-요약.md` 로 부여하고 삭제하지 않는다. 번호가 비면 무엇이 사라졌는지 알 수 없다.

## 출처

- Michael Nygard, "Documenting Architecture Decisions" (2011). 다섯 절 형식과 1~2페이지 기준의 원형
- ThoughtWorks Technology Radar, Lightweight Architecture Decision Records (Adopt). 위키가 아니라 소스 관리 안에 두라는 권고
- MADR. 선택지와 장단점을 표로 강제하는 파생 형식
- ISO/IEC/IEEE 42010. 아키텍처 기술에 결정과 근거를 포함하도록 요구하는 국제 표준
