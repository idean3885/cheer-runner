# 기획 의도와 첫 릴리스 범위

## 의도

```
1. 달리기 시작
2. 특정 지점 도달 시 화면을 터치해 현재 위치를 목표로 지정
3. 그렇게 N개 지정 → 순서 기록
4. 달리기 완료
5. 다음 달리기에서 그 코스를 뛰면, 목표 지점 도달 시 알림 → 응원 효과
```

기본기는 셋이다 — **GPS, 페이스 측정, 목표 사이 템포.**

## 주행에 두 종류가 있다

| | 기록 주행 | 따라가기 주행 |
|---|---|---|
| 언제 | 코스를 처음 달릴 때 | 그 코스를 다시 달릴 때 |
| 사용자가 하는 일 | 힘든 자리에서 화면을 터치 | 달리기만 한다 |
| 앱이 하는 일 | 그 순간의 위치를 지점으로 기록 | 지점 도달을 알리고 응원 |
| 남는 것 | 순서가 있는 지점 목록 | 구간별 템포 기록 |

배타가 아니다. 기존 코스를 달리다 지점을 하나 더 찍는 경우가 있으므로 한 주행 안에서 겹칠 수 있다.

## 구간은 내가 의미를 준 지점으로 나뉜다

다른 러닝 앱은 100m·1km·시간처럼 균일한 단위로 구간을 끊는다. 그 단위에는 뜻이 없다. 이 앱은 **내가 힘들었던 자리로** 끊는다. "3구간이 8분 10초" 가 아니라 "그 언덕 구간이 8분 10초" 가 된다.

"목표 사이 템포" 를 기본기로 둔 것이 이 뜻이다.

## 응원이 보상이다

점수도 배지도 아니다. 힘든 자리에 닿았을 때 앱이 그걸 알고 있다는 것 자체가 보상이다. 그 자리는 사용자가 직접 표시한 곳이므로 앱은 언제 응원해야 하는지 안다.

## 지점을 만드는 세 경로

지점을 만드는 방법이 셋이고, 갈리는 기준은 **사용자가 이미 무엇을 알고 있어야 하는가** 다.

| | 경로 | 언제 | 알고 있어야 하는 것 | 필요한 화면 |
|---|---|---|---|---|
| A | 달리며 터치 | 주행 중 | 없음. 지금 힘들면 누른다 | 큰 버튼 하나 |
| B | 내 트랙에 사후 추가 | 주행 직후 | 방금의 기억 | 내 트랙만 그린 지도 |
| C | 지도에서 사전 지정 | 아무 때 | 그 지역 지리 | 자유 지도, 검색, 주소 |

### 여기서 기능이 갈린다

요구 지식만이 아니라 성격이 다르다.

- **A·B 는 지나간 자리에 표시한다.** 내가 실제로 그 좌표를 통과했으므로, 같은 코스를 다시 달리면 반경 안에 반드시 든다
- **C 는 가보지 않은 자리에 예약한다.** 지도에서 찍은 점을 실제 경로가 안 지날 수 있고, 그러면 알림이 오지 않는다. 사용자는 앱이 고장났다고 본다

이 차이가 기능을 나누는 근거다. C 를 넣을 때는 **"이 지점은 아직 지나간 적이 없습니다"** 표시가 함께 가야 한다. 그게 없으면 C 는 조용히 실패하는 기능이 된다.

### B 의 설계 요점

핀을 **트랙 위로 붙인다.** 탭은 2차원으로 받고 가장 가까운 트랙 점으로 스냅해 1차원 선택으로 만든다. 임의 좌표를 허용하면 그 순간 B 가 C 가 되고 C 의 위험까지 따라온다.

그래서 B 의 지도는 C 의 지도보다 가볍다. 역할이 다르다 — C 는 지도가 **탐색** 도구지만 B 는 **확인** 도구다. 내 트랙만 보이면 되고 검색·주소·다른 장소가 필요 없다.

첫 릴리스의 B 는 지도 없이 낸다. B 의 본질은 트랙 위 한 점 고르기이고 그건 1차원 선택이므로, 종료 요약 화면에 트랙을 100m 간격으로 목록화하고 항목을 눌러 지점으로 올린다.

```
2.1km · 12분 30초 · 페이스 5'57"   [지점으로]
2.2km · 13분 05초 · 페이스 5'50"   [지점으로]
```

방금 달린 직후라면 "그 언덕이 2km 쯤" 이 붙는다. 개발 검증에는 충분하고, 지인에게 넘길 때 지도로 승격한다.

## 첫 릴리스에 있는 것

| 기능 | 내용 |
|---|---|
| 주행 시작·종료 | 버튼 하나로 토글. 시작은 사용자 행위로만 |
| 위치 추적 | 백그라운드 포함. 화면을 끄고 달릴 수 있어야 한다 |
| 거리·시간·페이스 | 현재 페이스와 전체 페이스 |
| 지점 지정 (A) | 달리는 중 화면 터치 → 현재 위치를 지점으로 |
| 지점 지정 (B) | 종료 요약에서 트랙 목록 항목을 지점으로 승격 |
| 코스 저장 | 지점 목록에 이름을 붙여 저장 |
| 코스 선택 | 저장된 코스 목록에서 골라 시작 |
| 도달 알림 | 지점 반경 안에 들면 음성 + 알림으로 응원 |
| 구간 템포 | 지점 사이 거리·시간·페이스. 도달할 때 읽어준다 |
| 종료 요약 | 전체 거리·시간·페이스, 구간 목록, 트랙 목록 |
| 모의 주행 | 개발용 토글. 기록된 트랙을 실제 경로로 흘려 넣는다 |

## 첫 릴리스에 없는 것

미루는 것이지 버리는 것이 아니다. 순서를 정한 이유를 함께 적는다.

| 미루는 것 | 왜 |
|---|---|
| 지도 화면 | A 는 지도가 필요 없고 B 는 목록으로 대신한다. 코스 선택도 목록으로 된다 |
| 경로 트랙 그리기 | 지도가 없으면 그릴 곳이 없다. 지도와 함께 온다 |
| 지점 지정 (C) | 도달 보장이 없어 성격이 다르다. 별 기능으로 가른다 |
| 피버·점수 | 응원이 먼저 통하는지 봐야 한다. 안 통하면 점수를 얹어도 안 통한다 |
| 강아지·배지 | 점수 위에 서는 것이므로 점수 뒤 |
| 지점 삭제·순서 편집 | 첫 릴리스에서는 코스를 다시 만드는 게 더 빠르다 |
| 주행 기록 목록 | 종료 요약만 있으면 한 번은 돌아본다 |
| 보고서 전송 | 개발 계측이다. 필요해지면 그때 |

## 확인을 네 층으로 나눈다

이 앱은 손으로 시험하기 어렵다. 선행 검증에서 결함 하나 확인에 20분이 들었고, 그래서 결함이 몰려서 뒤늦게 드러났다.

| 층 | 무엇을 보나 | 실외 | 비용 |
|---|---|---|---|
| 0 | **백그라운드 위치 수신 + 화면 꺼진 상태의 소리** | 5분 산책 | 반나절 |
| 1 | 거리·페이스·구간 템포·도달 판정·결손 처리 | 없음 | 0 |
| 2 | 조작·알림·음성·저장·요약·상태 전이 | 없음 | 분 단위 |
| 3 | GPS 정확도·도플러 속도 품질·배터리 | 30분 러닝 | 30분+ |

### 0 단계를 맨 앞에 두는 이유

위험 순서와 편의 순서가 다르다. 편의로 보면 모킹으로 기능을 다 만들고 마지막에 실측하는 것이 빠르다. 그런데 **아직 확인되지 않은 최대 위험**이 그 마지막에 숨는다.

선행 검증으로 확인한 것은 **웹**의 백그라운드 불가다. 네이티브에서 되는 것은 거의 확실하지만 확인된 것은 아니다. 권한 흐름, 백그라운드 작업 등록, 제조사 배터리 관리가 각각 걸릴 수 있다. 만든 것을 다 쌓고 마지막에 막히면 쌓은 것 전부가 걸린다.

그래서 **버릴 코드**로 위치만 받는 최소 앱을 만들어 먼저 찍는다. 화면도 도메인도 없이 수신 건수만 세면 된다. 소리도 같이 본다 — 화면이 꺼진 상태에서 음성이 실제로 들리는지는 같은 조건에서 확인되므로 한 번에 묶는다.

### 1 층과 2 층은 한 구현을 공유한다

위치 포트에 재생 어댑터를 끼우면 CI 단위 시험과 기기 모의 주행이 같은 장치로 해결된다. 근거는 [ADR 0004](adr/0004-replay-adapter.md).

### 모킹이 못 보는 것

초록불을 "됩니다" 로 읽지 않기 위해 적어둔다.

| | 모킹으로 보이는 것 | 기기에서만 보이는 것 |
|---|---|---|
| 음성 | 올바른 시점에 올바른 문구로 호출됐는가 | 화면 꺼진 상태에서 실제로 들리는가 |
| 알림 | 발행 요청이 갔는가 | 잠금화면에 떴는가, 소리·진동이 났는가 |
| 위치 | 어댑터가 값을 옳게 옮겼는가 | 백그라운드에서 계속 오는가 |

호출됐다는 것과 들렸다는 것은 다른 사실이다. 선행 검증에서 정확히 이 틈에 빠졌다 — 오디오가 "재생 중" 으로 보이는데 실제로는 꺼져 있었다.

## 다음 릴리스를 여는 조건

첫 릴리스로 확인할 것은 하나다. **같은 코스를 두 번째 달릴 때, 지점에서 오는 응원이 실제로 도움이 되는가.**

되면 지도와 트랙을 붙여 코스를 눈으로 보게 하고, 그다음 피버와 점수를 얹는다. 안 되면 응원 방식을 먼저 고친다 — 문구, 시점, 음성 대 진동. 점수로 덮지 않는다.
